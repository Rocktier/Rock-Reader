## 二、鸿蒙生态三项：接入路径与代价（已查证）

### 2.1 服务卡片 —— 零冲突，随时可做

官方路径（API 10+，我们工程满足）：DevEco 右键 entry → New → Service Widget → Dynamic Widget，
共包方式生成三件套：

- `EntryFormAbility.ets`（FormExtensionAbility，卡片生命周期：创建/销毁/刷新）
- `WidgetCard.ets`（卡片 UI，ArkTS 声明式）
- `form_config.json`（支持的外观规格）

交互两种：动态卡片 `postCardAction`，静态卡片 `FormLink`（router/message/call 三种事件）。

**Rock阅读的卡片设计（建议 2×2 与 2×4 两个规格）**：

```
┌─────────────────┐   ┌──────────────────────────┐
│ Rock阅读        │   │ Rock阅读                 │
│ ━━━━━━━━━ 62%   │   │ 《三体》 刘慈欣           │
│ 《三体》         │   │ ━━━━━━━━━━━━ 62%         │
│ 刘慈欣 · 第14章  │   │ 第 14 章 · 还剩约 23 分钟 │
│ [ 继续读 ]       │   │ [ 继续读 ]  [ 朗读 ]      │
└─────────────────┘   └──────────────────────────┘
```

- 点「继续读」→ `FormLink action:"router"` 带 `params:{ bookId }` → EntryAbility 收到参数
  直达 Reader 页并定位到 progress 表里的 chapter_index + char_offset（**地基已有**）。
- 点「朗读」→ `action:"call"` 后台拉起（需 `KEEP_BACKGROUND_RUNNING`，此按钮**建议不做**，
  会引入常驻权限，破坏零权限叙事；2×4 规格只放「继续读」）。
- 卡片刷新时机：`persistProgress(force)` 落盘后 `updateForm`（有节流，不必每页刷）。

**代价**：新增 1 个 Ability + 1 卡片页 + module.json5 注册 + 图标资源，约 300-500 行。
**验证**：模拟器可添卡片到桌面（`aa start` 后桌面长按 → 服务卡片）；点击跳转需真机确认。

### 2.2 智慧搜索（融合搜索）—— 半冲突，需拍板「索引范围」

官方机制：索引源应用调 `SearchAbility.insert/update/delete` 建索引，全局搜索（桌面下拉）可搜到；
权限 `ohos.permission.ACCESS_SEARCH_SERVICE`；本机索引用 `DEFAULT_GROUP` 群组（**不经过账号、不联网**）。

**冲突点**：这是 Rock阅读第一个「让数据离开应用进程」的能力——书名/作者会进入系统索引域。
**收缩方案（我建议的）**：

- **只索引书籍元数据**（书名、作者、格式、导入时间），**不索引正文内容**。
  对外叙事可以是「让系统搜到你的书，不搜你读过的内容」——反而比索引正文更符合人设。
- 用户可在设置里关掉（默认关还是默认开，需拍板；我倾向**默认关**，保持零权限口碑，
  设置里给一行「允许系统全局搜索到我的书籍」）。

**代价**：中。索引同步逻辑（导入/删除书时维护）、权限声明、隐私政策补一段、AGC 应用隐私
标签更新（新增权限必须申报，否则可能被驳回）。

### 2.3 小艺建议（意图框架）—— 有外部流程，越早申请越好

官方流程（Intents Kit）：AGC「开放能力管理」申请意图框架能力（1-3 工作日审核）→ 小艺开放平台
注册意图 → `insight_intent.json` 声明意图 → 应用内 `shareIntent` 共享 → 实现
`InsightIntentExecutor` 处理回调跳落地页。联调要真机 + 开发者选项「意图框架调试」+ 华为账号。

**Rock阅读的适配场景**：「继续读《三体》」习惯推荐卡片——共享的实体只有 bookId + 进度百分比。

**冲突点与判定**：
- 意图共享是**端侧学习**（系统根据习惯在桌面/负一屏出卡）；云侧「个人数据授权（SID）」
  是可选项，**我们不填 = 纯端侧闭环**，符合铁律。
- 但流程上绕不开 AGC 审核 + 真机验证，**实现本身不复杂，卡在外部**。

**行动建议：本周先提交 AGC 能力申请（零成本占位），实现排在服务卡片之后。**

### 2.4 远期牌：HarmonyOS 7 (API 26) 端侧 AI

官方已把「文搜图」做成端侧闭环（Core Vision Kit，本地特征向量 + 本地索引，数据不出端）。
同一范式未来大概率开放文本语义检索。届时「用大白话找书里的一段话」「这本书讲什么」
可以零云端接入。**现在要做的只有一件事：保持 1.0.5 的全文索引数据结构干净可复用，
不要把它写成只能服务当前 UI 的形状。**（技术预研可等 SDK 开放，现在不投人力。）

**一句话概括差距**：我们的**数据地基比想象中好**（锚点、会话记录、索引全在），

笔记跳回原文，这五项全都**不需要新能力，只需要把已有数据用起来**。

## 四、改进方案：分三批

### 批次 A —— 1.0.6「把已有的数据用起来」（零新权限，零联网，纯内功）

| # | 事项 | 做什么 | 相对工作量 | 对标 |
|---|---|---|---|---|
| A1 | **每本书独立排版** | ReaderPrefs 拆「全局默认 + per-book 覆盖」；新增 book_prefs 表（book_id 主键，存 levels/theme/fontFamily 的覆盖值，null=继承全局）；阅读页设置抽屉加「应用到所有书 / 恢复全局设置」；首次改排版时提示「仅这本书 / 所有书」 | 中（DB + 抽屉 + 读取链） | 静读天下精髓，Apple Books/Kindle 都有 |
| A2 | **自动日夜切换** | 主题加「自动」档：日出自日落（可按经纬度粗算或用固定 6:30/18:30，加「跟随系统深浅」选项复用私记已实现的 resolveDark(ctx.config.colorMode) 逻辑）；切换时 `updateForm` 通知卡片 | 小（逻辑可移植） | 三家全有 |
| A3 | **本章/全书剩余时间** | segBar 现有 percent 旁加「本章还剩约 N 分钟」；用 read_sessions 统计个人 WPM（字符/分钟），按当前章剩余字符估算；新书无历史时用默认 300 字/分并标注「估计」 | 小中 | Apple Books/Kindle |
| A4 | **阅读目标 + 连续天数** | Stats 页（已有 sessions + 「读得最多的书」）加：今日进度环/条、可设每日目标（默认 20 分钟）、连续阅读天数（私记 todayKey  streak 逻辑同源可借鉴）、本周达成几天 | 小 | 三家全有 |
| A5 | **笔记/书签跳回原文** | 抽屉里书签/摘录列表项点击 → openChapter(chapter_index, char_offset)（**API 已在**）；列表按章节分组、显示章节名；顺手支持高亮多色（4 色，与 Apple Books 对齐） | 小 | 三家全有 |

批次 A 合计约一个迭代周期，用户可感知强（「这阅读器记得我这本书的设置」是口碑点），
且**完全在铁律内**：零新权限、零联网、包体几乎不变。
