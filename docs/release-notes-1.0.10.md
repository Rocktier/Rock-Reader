## 三、本版具体改了什么

### 3.1 划词存摘录（1.0.9 只做到「能复制」）

- 长按正文 → **系统选区**出现（可拖手柄扩选）→ 系统菜单里选「加入摘录」
  （系统默认项占满 4 个槽位，自定义项在 `⌄` 溢出菜单里）
- 摘录面板**预填你选中的那一句**，标题默认「存这段摘录」
- 五色可选、可以再写一句注 —— 与 1.0.9 的摘录面板同一套
- 面板里多一行提示：选区太短时告诉你「可以拖正文里的手柄扩大选区」

### 3.2 阅读页屏幕亮度 + 常亮

- 设置里新增「屏幕」区：**6 档亮度**（很暗 → 很亮）+ **常亮开关**
- 亮度是**阅读页自己的**亮度，不动系统全局亮度
- 离开阅读页自动还原系统亮度与常亮状态；档位会记住，下次进来还是你上次那档
- ⚠️ 亮度只影响本应用阅读页，不影响其他应用，也不改系统设置

### 3.3 整页快照的老办法没删

- 1.0.9 的「长按定格整页 → 手动裁剪」降级为中央菜单里的「摘录」按钮
  （长按必须完整让给系统，否则系统选区根本不出现）

## 四、技术备注（给以后接手的人）

### 4.1 划词的四个坑（都是模拟器实测踩出来的）

1. **正文 Text 上不能挂 `.gesture(LongPressGesture())`** ——
   自定义手势会**抢赢** Text 自带的长按选词，实测是「零选区、零菜单、UI 树 0 个 TextMenu」。
   长按必须**完整让给系统**。
2. **`editMenuOptions.onMenuItemClick` 必须返回 `false`** ——
   返回 `true` 是完全拦截系统默认逻辑，系统浮动菜单会**赖在屏幕上不收**。
   返回 `false` 才走系统默认的「收起菜单」。
3. **撤选区用 `TextController.setTextSelection(0, 0)` + `closeSelectionMenu()`** ——
   本工程 compileSdk 20 的 `UIContext` **没有** `clearFocus`（API 26 才有），
   切 `textSelectable` 也撤不掉已建立的选区。controller 要走 `Text(content, { controller })`，
   `TextAttribute` 上没有这两个方法。
4. **系统长按中文默认只选 1 个字** ⇒ 任何「少于 N 字就丢弃」的门槛都会把用户点击变成死路。
   现在的门槛只挡**空选区**，偏短只做提示。

### 4.2 ⭐ 划词**不需要**升 compileSdk（推翻 10-30 的误判）

1.0.9 的 release notes 里写着「划词 API 都是 26 起，本工程 20 用不了」—— **这是错的**，
10-30 写文档时没有回查 SDK 声明。实测结论：

| API | 起始版本 | 本工程（compileSdk 20）可用 |
|---|---|---|
| `Text.onTextSelectionChange` | 11 | ✅ |
| `Text.textSelectable` | 12 | ✅ |
| `Text.editMenuOptions` | 12 | ✅ |
| `SelectionContainer` 组件 | 26 | ❌（用不上，也不需要） |

⇒ **别再为了划词去升 compileSdk**。

### 4.3 依赖插桩铁律（第 7 次同型）

屏幕亮度的标签原先写成 `this.brightnessLabel()`（方法体里读 prefs），
ArkUI V1 的依赖插桩**追不到** ⇒ 切了档位界面不刷新。
已改成**就地读 `@State`**：`Text(brightnessLabelOf(this.brightnessIndex))`。

### 4.4 屏幕相关的两个 API 事实

- `window` 模块属于 **`@kit.ArkUI`**（本 SDK **没有** `@kit.WindowKit`）。
- `window.setWindowBrightness(-1)` = 恢复系统亮度；`window.setKeepScreenOn` 是**窗口级**副作用
  ⇒ 必须**成对还原**，否则会把全局常亮状态带跑。
