### ⚠️ 本次唯一的后台操作新项：后台模式 → 音频

入口：**版本管理 → 权限管理 → 后台模式 → 音频**（勾选 + 填用途）。

用途说明可照抄：

```
朗读功能需要后台音频能力：用户在切到后台或锁屏时继续听书。
音频由本机语音合成引擎生成，不联网、不上传、不录音。
```

为什么必须勾：1.0.8 在 `module.json5` 的 EntryAbility 下新增了
`backgroundModes: ["audioPlayback"]`，包里带着这个声明，**不勾选用途就会被驳回**。

**这条不影响「零权限」叙事**：
`backgroundModes` 是「后台模式声明」不是权限，权限清单（`requestPermissions`）依然是空的。
隐私政策**本次无需改动** —— 后台音频不涉及任何新的数据采集：
没有新权限、没有新的数据外流路径，音源是书里已有的文字、输出是本机合成的音频。
（对照：1.0.6 那次必须改政策，是因为麦克风是**真权限 + 真采集**。）

## 三、写这段时的六条取舍（给党哥自己看，不上传）

1. **滚屏放第一条**——这是静读天下的招牌能力，通勤场景直接命中，
   也是这一版最容易被用户感知的「肉眼可见的新按钮」。
2. **速度档用「几秒一页」而不是「字/分钟」**——本应用是**分页渲染**（不是连续滚动），
   「按行滚动」在这个架构里没有对应物；而「几秒翻一页」用户能直接换算成
   「一章要读多久」—— 顺带解释了浮条上「还剩多久」为什么可信。
3. **自动滚屏不写成 AI/智能阅读**——它就是定时翻页，别夸大。
   浮条上「还剩多久读完」是本机按剩余页数 × 当前档位算的，不是预测模型。
4. **媒体会话那条只写用户能复述的现象**——「切到后台或锁屏就停了」，
   不写「接入 AVSession」。用户在商店页看到的是体验，不是 API 名。
5. **主动交代后台音频**——这条必须在正文里说清楚，因为 AGC 后台要勾「后台模式→音频」，
   审核员一定会对照。与其让它看起来像藏了什么，不如明说
   「它是系统能力、不是权限、不上传」。**说清楚 = 少一轮驳回。**
6. **一个字不提语音识别准确率**——那是 Rock私记 的能力，
   而且模拟器没有离线识别引擎，识别效果必须真机验过再说（家族纪律：没实测就不写）。

## 四、技术备注（留存，不上传）

**1.0.8 的两项新能力（模拟器全量实测通过）**

- **自动滚动**（`data/AutoScroll.ets` 纯逻辑 + `Reader.ets` UI + `ReaderPrefs` 速度档持久化）
  - 速度档以「每页停留秒数」计：`[8, 6, 4, 3, 2]`，默认 4 秒/页，存 `scroll_speed` 偏好项。
  - 跨章自动续下一章；全书读完自动停 + toast「已到全书末尾」。
  - 手动翻页 / 横滑 = 用户接管 ⇒ 立刻暂停（保留档位，用户可从浮条继续）。
  - 回后台停表但不改状态（独立 `scrollSuspended` 标志），回前台自动续滚。
- **TTS 媒体会话**（`engine/tts/AvSession.ets` SDK 封装 + `AvSessionState.ets` 纯逻辑）
  - `AVSession` + `setAVPlaybackState` / `setAVMetadata` / `setLaunchAbility` / `on(play|pause|stop|setSpeed)`，
    全部 try/catch 降级：**媒体会话失败绝不连累朗读本身**。
  - `module.json5` 声明 `backgroundModes: ["audioPlayback"]`（合法值是 `audioPlayback` 不是 `audio`，写错直接编译失败）。

**三个踩坑与修正（均已实测复验）**

1. **滚屏 × 朗读必须互斥**——同时开时，滚屏每翻一页就 `tts.seekTo(range.start)` 一次，
   音频被反复重载（实测日志：`onStart` 每 2 秒一个新 id、`onComplete stale, dropped`）。
   修法：双向互斥 + toast 告知（开朗读先停滚屏；开滚屏先停朗读）。
2. **浮层与滚屏的联动，两次重构才收敛**——
   第一版「开浮层暂停 / 关浮层恢复」要在 6 处 `showXxx` 赋值点同步**影子状态**，
   漏一处就是「菜单关掉了还在背后滚」的幽灵 bug（10-28 实测踩到）。
   最终改成**到点才判断**：`onScrollTick()` 里就地判浮层是否开着，开着就不翻页，
   浮层一关，下一拍自然继续。**状态只有 `scrollState` 一处，没有第二套需要同步的东西。**
3. **菜单「滚屏」按钮三态自描述**——OFF→`滚屏` / RUNNING→`停滚屏` / PAUSED→`继续滚屏`。
   ⚠️ **PAUSED 必须映射到「继续」不能映射到「关掉」**
   （用户想继续、结果被关掉 = 静默的期望违背），已用单测守死。

**ArkUI V1 的两条纪律（本次再次确认）**
- `@State` 必须**就地读进表达式**，藏进 getter / 方法体里依赖插桩追不到 ⇒ 文案定格。
  菜单按钮用就地三元展开，不用 `scrollMenuLabel()` 方法。
- `build()` 不整体重跑，`if` 的分支条件按首次求值定型。

**模拟器实测清单（2026-10-28，全部通过）**
- 底栏 6 按钮布局不挤；浮条出现在页脚上方，内容正确（暂停 / 4秒每页 / 约 2 分钟 / 关闭）
- 自动翻页 4/10 → 10/10 并**跨章推进**（第 1 节 → 第 2 节 → 第 3 节）
- 手动翻页自动暂停（浮条按钮由「暂停」变「继续」）
- 速度档循环 4→3→2 秒/页，且**重进阅读页仍是 2 秒/页**（持久化生效）
- 全书读完自动停 + toast + 浮条收起
- **菜单打开时浮条隐藏，且开 10 秒页码纹丝不动（不空跑）**；关菜单自动恢复
