# RockReader：一个自己造轮子的鸿蒙电子书阅读器，装完才 3.4MB、断网照样看

RockReader 是我自己开发的一个跑在鸿蒙（HarmonyOS）上的电子书阅读器，个人项目。排版这块自己写的，zip 解压、EPUB 解析也没用现成库。今天把它捞出来，正经介绍一遍。

## RockReader 是什么

中文名叫「Rock阅读」，属于 Rocktier 的「Rock」软件家族。支持 TXT 和 EPUB 两种主流格式，瞄准 HarmonyOS 5.0.4 及以上。

打包出来是个 HAP 文件，你就当成鸿蒙里的安装包。整个安装包 3.4 MB 上下，后面展开讲。

## 三条铁律，是它的脾气

做它的时候给自己定了三条规矩，叫「家族统一铁律」。

**第一条，极致快。** 翻书最怕卡，这个没什么好说的。它整章只排版一次，把每一行的位置算好存成一张「页表」，之后翻页只换显示的字符串，不再重新测量字体和行高。头一次打开费点劲，往后翻页就是换张纸，不重算，所以快。

**第二条，极致小。** 安装包死死压在 5 MB 的预算线内（现在 3.4 MB 上下：早期纯内核时代确实只有 115 KB，加上完整书架 UI、TTS 朗读、书签摘录、全文搜索之后才长到现在个子），一个第三方库都没引。zip、解压、XML 解析、UTF-8 解码全是自己写的。这么轴是有原因的：三方库一引进来，体积和依赖就跟着滚雪球，收不住。

**第三条，核心数据不联网。** 你的书、阅读进度、设置，永远不出这台设备。断网的时候功能照样完整，该看啥看啥。它不偷数据，也不靠联网才能用。

三条摆在一起，取向就很明白了：轻，快，不碰你的数据。

## 自研引擎那点事

再说下引擎。阅读内核是自己写的，zip 解包、DEFLATE 解压（压缩文件用的那套算法）、OPF 和 NCX 这些 EPUB 内部格式解析、UTF-8 解码，都是自己实现的，不 import 任何鸿蒙专属的东西（`@ohos`）。

这么折腾有个很实在的回报。这类代码是纯 TypeScript、不依赖设备，能在电脑上的 Node 里拿真实数据反复测穿，不用守着真机。项目配了 182 个单元测试，拿一本真实的出版级 EPUB（3.4 MB、11.7 万字）去跑，解析 7 毫秒，全文转文本 22 毫秒。

EPUB 是什么？你就当成把一堆网页和目录打包成的压缩包式电子书，所以要解 zip、读目录，再把网页内容抠成纯文字。这几样活儿都自己干了，没借现成的轮子。

## 字体，它不塞给你

很多阅读器一装就是好几个字体文件，一套通用中文字体得 9 到 11 MB，直接把「极致小」那条撞碎。

RockReader 不内置字体，直接把你系统里已经装好的字体列出来给你挑，本体零负担。开源字体的 GB2312 子集下载（楷体 3.27 MB、宋体 2.91 MB）还在规划中，当前版本没这个入口——等功能上线的时候，联网说明会一并给清楚。

## 它能干这些

- **书架与导入**：本地选书进沙箱、自动索引、落库，书架一眼看清。
- **TXT 全链路**：解析、分页、阅读页一条龙，纯文本书直接读。
- **EPUB 阅读**：zip 解包、OPF/NCX 目录、XHTML 转纯文本，整本出版书打开就能看。
- **阅读设置**：字号、行距、边距档位，章节目录跳转，昼夜主题切换，进度自动记忆。
- **书签 / 摘录 / 全文搜索**：读到哪儿想记号，随手打；全文搜索直达。
- **听书**：章级朗读、六档语速、定时停止（15/30/60 分钟）。
- **平板适配**：书架列数与阅读版心随屏宽自适应。
- **自动构建与发布**：代码推到公开仓库就走 GitHub Actions，单测加编译校验，打 tag 自动发 Release，附 HAP 和 SHA256 校验和。

## 怎么把它装到手机上

代码在公开仓库里，构建走 GitHub Actions 自动流水线。想要能装真机的包，用华为的 DevEco Studio 在本地电脑上构建，勾选自动签名即可（新版 DevEco 自带鸿蒙 SDK，不用额外下载），产物就能装到鸿蒙手机上跑。

## 大概就这些

RockReader 就是这样一个本地阅读器：依赖少，体积小，不联网，把看书这件事做得简单干净。代码目前保留所有权利（All rights reserved），可以阅读、fork 来学习参考。
