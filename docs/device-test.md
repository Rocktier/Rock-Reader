# 真机测试手册（Windows + DevEco Studio）

> 目的：本机（macOS 侧）没有鸿蒙环境，所有"只能在设备上验证"的项目都在这份清单里。
> 你按这个跑一遍，把不合预期的现象贴给我（第 5 节有日志命令），我来改。

---

## 1. 打开项目

1. DevEco Studio → **Open** → 选中目录 `Rock-Reader`（**选仓库根目录**，不要用向导新建工程）。
2. 首次打开会提示同步 / 安装依赖 → 同意。它可能自动补 `hvigor-config.json5` 里的版本信息，
   **这类本地改动不要提交**（见第 6 节）。
3. ✅ **实测结论（党哥 2026-09-18）**：新版 DevEco Studio **自带 HarmonyOS SDK（API 26）**，
   打开工程后**直接 Build 就能成功**，不需要另外下载 command-line-tools。
   （SDK 目录若做了联接 `LOCALAPPDATA\Huawei\Sdk → G:\HarmonyOS\Sdk`，记录见家族台账）
4. ⚠️ 若仍提示缺少 **HarmonyOS 5.0.4(16)** SDK：在 `build-profile.json5` 的 `default` 产物里
   把 `compatibleSdkVersion` 临时改成 `"6.0.0(20)"`（只改本地），或按提示下载该 SDK。
   （仓库里保持 16 是为了让 5.0.4 以上的机器都能装，见第 7 节）
5. 不需要真机也能先看 UI：**Previewer**（DevEco 右侧）可以预览页面；
   但**字体注册、文件选择器、graphics.text 排版**这类能力以真机为准。

## 2. 配置签名（必须，否则装不进手机）

DevEco Studio → **File → Project Structure → Signing Configs** → 勾选 **Automatically generate signature** → 登录华为账号 → 完成。

它会：生成调试证书 → **把你的手机 UDID 注册到 AGC** → 写入本地 `build-profile.json5` 的 `signingConfigs`。
签名文件与环境必须留在本地（`.gitignore` 已挡住 `*.p12 / *.cer / *.p7b / signing/`）。

## 3. 手机准备

- 设置 → 关于本机 → 连点「版本号」进入开发者模式
- 设置 → 系统和更新 → 开发人员选项 → 打开 **USB 调试**
- 数据线连接 → 手机弹「允许 USB 调试」→ 允许
- DevEco 右上角设备列表能看到你的手机即可

## 4. 真机验收清单（照着一条条看，括号里是**判据**）

统一前置：选择 product = **default**、buildMode = **debug**，点 ▶ Run。准备三本书：
① 一本 UTF-8 TXT ② 一本 GBK/GB18030 TXT ③ 那本真实 EPUB（`~/Downloads/rockreader-samples/` 里那本）。

### A. 关键路径（错一条就是 bug）

| # | 操作 | 期望（判据） |
|---|---|---|
| A1 | 冷启动（杀进程后点图标 → 看到书架） | **≤1 秒**，书架只列已导入的书，不自动跳进某本书 |
| A2 | 点 ＋ 导入 EPUB | 书籍标题 = **书的真实书名**（不是文件名）；书架出现该书 |
| A3 | 打开 EPUB → 点中间 → 点「目录」 | 目录标题与正文对得上（**第 4 项应显示「第一章 …」而不是「封面/版权页」**） |
| A4 | 点目录里的某一章 | 跳到该章第 1 页，页码变成 `1/N` |
| A5 | 点屏幕**左/右三分之一** | 上一页 / 下一页；到章首页再往前 → 上一章末页 |
| A6 | 手指**左右横滑** | 翻页（淡出→换页→淡入） |
| A7 | 点屏幕**中间** | 浮出上下细栏；再点中间 → 收起 |
| A8 | 点「A a」→ 改字号/行距/边距 → 返回 | **不跳页**（还停在原来那段文字附近）；行距立刻变化 |
| A9 | 设置里切「浅色」 | 整页变白底黑字，**状态栏的时间/电量也变黑**（若仍看不清就是 bug） |
| A10 | 设置里选一个系统字体 | 预览行与该字体一致；返回阅读页后正文生效，**不跳页** |
| A11 | 杀进程后重新打开这本书 | 回到上次位置（章 + 页），不是从第 1 页开始 |
| A12 | 长按书架上的书 → 移除 | 书从书架消失；**原文件还在手机里** |
| A13 | 设置 → 字体 → 点「下载」下一款字体（霞鹜文楷 13.3MB，建议在 Wi-Fi 下试） | 状态变成"下载中…"→"已就绪"；该字体出现在上方芯片行并**自动选中**；回阅读页正文变成这款字体 |
| A14 | 下载完一款后**杀进程重开** | 字体仍在芯片行里、仍能选中并生效（字体每次启动会重新注册） |
| A15 | 下载到一半断网 / 关掉联网权限 | 显示"下载未完成，可稍后再试"，**不弹窗**、不拦路；不会留下一个不能用的字体；阅读完全不受影响 |

### B. 最高风险项（重点，这条最容易出问题）

| # | 操作 | 判据 |
|---|---|---|
| **B1** | 设置 → 显示与亮度 → **字体大小调到最大**（或最小）→ 回阅读页 | 正文**最后一行的最后一个字必须完整可见**。若出现「最后一行被裁掉一半」「底部留白忽大忽小」，就是**测量与渲染断行不一致** —— 这是我知道的最大风险，请把这个现象告诉我 |
| B2 | 同上，再切几种字体 + 各档字号组合 | 同上（每种组合都要看末行） |
| B3 | 阅读页旋转屏幕 / 分屏（若有） | 能正常重排并停在原来的文字位置 |
| **B4** | **用"下载来的字体"阅读**（A13 之后） | 末行仍然完整。这条专门验证"测量端与渲染端挂了同一个字体文件"是否真的同源（实现上：渲染用 `registerFont`，测量用 `FontCollection.loadFontSync` 加载同一个文件） |

### C. 性能（有就记，没有也能测）

| # | 操作 | 期望 |
|---|---|---|
| C1 | 导入一本 50MB+ 的 TXT | 能导入成功；导入期间界面可接受（预计短暂卡顿，请记录大约几秒） |
| C2 | 打开那本 50MB 的书 → 连续快速翻 30 页 | 无明显掉帧、不白屏 |
| C3 | DevEco 的 **Profiler → 内存** | 打开一本大书后内存不随翻页持续增长（应稳定在"当前章 + 缓存"量级） |
| C4 | 打开一本 EPUB，翻到最后一章 | 全程无卡顿（整本解析本机实测 22ms，真机应更快） |

### D. 意外路径（不许崩）

| # | 操作 | 期望 |
|---|---|---|
| D1 | 导入一个改名为 `.txt` 的图片文件 | 提示「已导入，但目录解析失败」，**不崩** |
| D2 | 导入一个残缺的 EPUB（可用压缩软件解压后只打包一半） | 提示解析失败，**不崩**，书架里不出现脏数据 |
| D3 | 飞行模式 / 关闭本应用联网权限 | 功能与观感**完全不受影响**（当前版本本来就不联网） |
| D4 | 阅读中途按 Home 键 → 从最近任务回来 | 位置不丢（进度在页面隐藏时已落库） |

## 5. 出问题怎么给我日志

```bash
# DevEco 自带 hdc（在 SDK 的 toolchains 目录），或直接用 DevEco 的 Log 面板
hdc shell hilog | grep RockReader
```
应用日志统一带 `RockReader` 标签（`hilog.error` 里会打出 JSON 错误），把出错前后十几行贴给我即可。
如果是崩溃，把 DevEco **Log** 面板里 `FaultLogger` / `crash` 相关的段落也一起贴。

## 6. 本地改的东西不要提交

DevEco 打开工程后会自动改这些文件（都很正常，但**不该进仓库**）：

- `build-profile.json5`：追加 `signingConfigs`（你的证书路径与口令指纹）
- `hvigor-config.json5` / `oh-package-lock.json5`：版本信息与锁文件
- `local.properties`、`.idea/`

`.gitignore` 已经挡住密钥类文件与 `.idea/`，但 `build-profile.json5` 是**要进仓库的**，所以：
改完签名后，如果 git 提示该文件被改，**别提交**（`git checkout -- build-profile.json5` 还原即可）。
将来接 CI 签名时，证书走 GitHub Secrets，配置里只写占位路径。

## 7. 为什么是「兼容 API 16」而不是「只支持 HarmonyOS 6」

`build-profile.json5` 现状：
- `default` 产物（给用户/真机）：`compatibleSdkVersion = 5.0.4(16)`、`targetSdkVersion = 6.0.0(20)`、`runtimeOS = HarmonyOS`
- `ci` 产物（只做编译校验）：`compileSdkVersion = 20`、`runtimeOS = OpenHarmony`

含义：**HarmonyOS 5.0.4 及以上的机器都能装**（覆盖面更大），代码只用 API 16 以下就有的能力
（`graphics.text` API 12+、`getSystemFontList` API 10+，都够）。另立 `ci` 产物做 CI 编译校验
（CI 拿不到 HarmonyOS SDK，只能用公开的 OpenHarmony SDK）—— 这也是为什么 **CI 的 HAP 不能装手机**。

**两个产物别混淆**（都有用，用途不同）：

| 产物 | 谁产出 | 体积 | 能装手机吗 |
|---|---|---|---|
| `ci`（OpenHarmony，未签名） | **GitHub Actions** | 135.7 KB | ❌ 只做编译校验 |
| `default`（HarmonyOS，调试签名） | **DevEco Studio（本机）** | 实测 436 KB | ✅ 装你自己的手机 |

真机测试一律用 DevEco 构建的那个。
