## 二、更新说明正文（直接粘贴这段）

```
【新增】桌面续读卡片
长按桌面上的应用图标，就能把「续读卡片」添加到桌面，有 2×2 和 2×4 两种尺寸。
卡片上显示正在读的书名、作者、当前章节和阅读进度，以及本章还剩下的时间；
点一下卡片，直接回到上次读到的那一页，边读边更新。

【新增】每本书记住自己的排版
字号、行距、页边距、字重、字体可以按书单独调整，互不干扰——绘本用大字号、
小说用小字号，不用再两头改。改完还能一键「应用到所有书」，或随时「恢复全局」。

【新增】日夜自动切换
阅读主题新增「自动」：早上 6:30 自动转浅色，晚上 18:30 自动转深色。
夜里读到那个点会自己变暗，不用手动切。

【新增】本章还剩多久
打开阅读菜单，底部会告诉你本章还剩下的阅读时间，翻页跟着变。

【新增】每日阅读目标
统计页顶部新增目标卡，点一下切换每日目标（10 / 20 / 30 / 60 分钟，或关闭），
进度条一眼看到今天读了多少、还差多少。

【隐私】仍然不联网、零权限
本次更新没有新增任何权限。桌面卡片上的书名和进度全部来自本机阅读记录，
不上传、不同步，阅读依然全程离线。
```

正文 6 条 / 约 330 字。

## 三、写这段时的六条取舍（给党哥自己看，不上传）

1. **卡片放第一条**——这是这一版唯一「超出应用边界」的新能力，也是最有说服力的
   一眼差异点；放后面会被排版那几条埋掉。
2. **「点一下回到上次读到的那一页」而不是「跳转到阅读页」**——审核员和用户关心的
   都是「能不能一步到位」，不是跳转的技术事实。真机实测过：点桌面卡片精确回到
   第 7 章第 9/10 页。
3. **不提技术名词**——不写 FormExtensionAbility、ArkTS 卡片、formBindingData。
4. **「本章还剩多久」写明触发位置**（打开阅读菜单时）—否则用户找不到会当成 bug。
   它刻意不做成常驻，是为了不打扰阅读。
5. **零权限再申一次**——新增了桌面形态，最容易引出的疑虑就是「它是不是要把我的
   阅读数据上传给桌面/云」。主动交代比被问再解释便宜。事实也站得住：
   `module.json5` 里连 `requestPermissions` 节点都没有。
6. **进度算法的事一个字没写**——这一版代码里确实在改「按真实字数算进度」
   （旧的按章节数算，实测虚高近一倍：显示 8.67% vs 真实 4.66%），
   但**普查链路本轮没跑起来，运行时仍走旧口径**，等于还没兑现。
   写了就是虚假宣传，而且给用户平白添一个「为什么没变」的疑问。留到 1.0.7。

## 四、技术备注（留存，不上传）

**服务卡片**
- 三件套：`ets/entryformability/EntryFormAbility.ets`、
  `ets/widget/pages/WidgetCard.ets`、`resources/base/profile/form_config.json`，
  module.json5 注册 `extensionAbilities(type: form)`
- 数据层新增 `ets/data/CardData.ets`：progress + chapters → formBindingData 推送
- 机制备忘：跳转用全局 `postCardAction(this, {action:'router', abilityName, params})`；
  尺寸要用 API20+ 的 `RunningFormInfo`（**`FormInfo` 没有 formId/dimension**，用错编译报错）
- 真机全验证：2×2 / 2×4 都上过桌面；点击精确回位；边读边更新（7%→8%，章节与剩余同步）
- 顺手修的 bug：卡片推送节流顺序是「先写快照 → 再判断推不推」，被限流吞掉的很可能
  就是离开阅读页的最后一次进展，再也补不上 → `pushCardUpdate(ctx, force)`，
  `persistProgress(force)` 的最后一击穿透限流

**批次 A 四项**（1.0.5 之后首次上架）
- A1 每本书独立排版 `book_pref_<bookId>` 覆盖层 + 「应用到所有书/恢复全局」
- A2 自动昼夜 `resolveTheme/isNightHour`，6:30/18:30
- A3 本章剩余时间 `chapterLeftText`
- A4 每日目标 关→10→20→30→60 循环

**已知未完成**
