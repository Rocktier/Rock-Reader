# 对标顶级产品：两个应用还差什么（2026-11-03 全量代码盘点版）

> 依据：Rock阅读（54 个 .ets / 约 12,400 行，HEAD `5a4c0f4`，1.0.9）+ Rock私记（46 个 .ets / 11,659 行，HEAD `b58c614`，1.0.7）
> 逐文件 grep + 精读盘点，每条均有 `文件:行号` 凭据。取代 `生态融入与对标改进方案-2026-10-25.md` 的对账表作为排期依据。
> 对标对象：阅读 = Apple Books / Kindle / 静读天下；私记 = Day One / Journey / Notion 日记。

## 零、一句话结论

**Rock阅读 已经是一个「能用的完整阅读器」，差的是「打磨度」**——数据地基（会话/字数/进度/索引）比想象中好，
缺的是把已有数据变成体验的那一层（划词查词、导入反馈、动画档位、常亮）。

**Rock私记 已经是一个「加密做得很硬的日记本」，差的是「内容组织的表达力」**——
安全/时间胶囊/统计骨架都在，缺的是富文本完整度、年度回顾这类「值得截图分享」的东西。

两者共同的硬伤是：**所有新功能都没有在真机上验过**（党哥无真机，模拟器没有 ASR 引擎）。
这比任何功能缺口都更值得优先解决 —— 未验证的功能等于不存在。

## 一、Rock阅读 的差距

### A. 硬差距（缺失且用户天天感知）

| # | 差距 | 现状证据 | 顶级产品怎么做 | 实现代价 |
|---|---|---|---|---|
| 1 | **长按查词 / 划词弹窗** | 全仓 `dictionary\|词典\|查词` = **0 命中**；正文是单个 `Text`，无选区 | Apple Books/Kindle/静读天下：长按弹词卡（释义 + 例句 + 发音 + 加入生词本） | **SDK 卡死**：`SelectionContainer` / `onTextSelectionChange` / `editMenuOptions` 全是 **API 26 起**，本工程 `compileSdk 20` 编译不过（ERROR 10505001）⇒ 要么升 compileSdk，要么降级为「点词」手动查词 |
| 2 | **导入进度 + 导入移出主线程** | `BookImporter.ets:10-21` 明文决策：导入解析**不上 taskpool**，主线程同步；大 EPUB 整本读进内存（上限 100MB） | 所有主流阅读 App：导入有进度条、可取消、后台化 | 中。改导入链路 + 解析搬 taskpool，**不动解析正确性** |
| 3 | **翻页动画多档** | `Reader.ets:13` 注释「v1 不做仿真翻页」；现只有淡入淡出 + 跟手拖拽，**无配置入口** | 静读天下：仿真/覆盖/滑动/无动画/自动滚动 五选一 | 中-大（要改渲染管线） |
| 4 | **屏幕常亮 + 阅读页独立亮度** | 全仓 `keepScreenOn` / `setWindowBrightness` = **0 命中** | 通勤场景刚需：不碰屏幕就息屏，阅读体验直接崩 | 小（都是系统 API，不涉权限） |
| 5 | **备份 / 恢复** | `EntryBackupAbility.ets:6-13` 是**空壳**，只打日志；但 `module.json5` 里 `allowToBackupRestore: true` | 用户换机/重装是最大数据丢失场景 | 小-中。**注意：这是「我们领先」定位的漏洞** —— 私记做了系统备份对账，阅读没有 |

### B. 需要新能力 / 外部流程

| # | 差距 | 卡在哪 | 建议 |
|---|---|---|---|
| 6 | **用户导入自有字体 ttf/otf** | `FontCatalog.ets:52-80` 楷体条目**整段被注释**（`hasDownloadable()` 恒 false ⇒「更多字体·下载」整段 UI 不显示）；`FontStore.downloaded()` 只认内置 catalog | **零权限可做**（系统 picker 选字体文件）。静读天下有这功能 |

### C. 主动取舍（不是落后，别被对标表带偏）

- 跨端接续（iCloud / Whispersync）· 内容源/书城 · 云端 AI · **PDF**（`MarkupParser.ets:8-12` 注明要另开 `@kit.PDFKit` 一条路）· 漫画 CBZ/CBR（**渲染管线是真正大头**，不是解析器）
- 主题**不**跟随系统深色（方向是「主题→系统」，与 Apple Books 相反，刻意解耦）

### D. 我们领先（要当卖点讲）

- **零权限零联网**（`module.json5` 无 `requestPermissions`）
- **AVSession 后台朗读**（1.0.8）—— 锁屏/通知栏/耳机键控，国内 HarmonyOS 阅读器里少见
- **自动滚屏**（1.0.8，5 档速度，浮层互斥，后台挂起回前台续滚）
- **无障碍**：`accessibilityText` + `responseRegion` 热区撑到 44vp + 真 Button 语义（Apple Books 有，国产多数没有）
- **正文净化（去广告）+ 简繁转换**
- **每本书独立排版** + 自动昼夜（Apple/Kindle/静读天下都有，我们持平）

## 二、Rock私记 的差距

### A. 硬差距（缺失且用户天天感知）

| # | 差距 | 现状证据 | 顶级产品怎么做 | 实现代价 |
|---|---|---|---|---|
| 1 | **富文本完整度** | 工具栏只有 **B / I / 列表前缀 / 图片 / 语音**（`Editor.ets:1199-1281`）；**无标题/引用/分割线/代码块/高亮/对齐/清单**；`h` 块数据层有（`NoteBlocks.ets:14-43`）但**只能靠手打 `# ` 触发**；列表按钮只插 `- ` 文本，**界面不渲染项目符号/缩进** | Notion/Day One：完整块编辑器 | 中。数据层已有 4 种块 ⇒ 主要是加工具栏 + 渲染 |
| 2 | **图片不在正文流内** | 图片以**缩略图行**呈现在编辑器**下方**（`Editor.ets:1500-1533`），正文流里是空行；块模型里 img 块不参与行文本往返（`NoteBridge.ets:104-106`） | 所有主流日记：图在段落中间，可拖动排序 | 中 |
| 3 | **年度回顾 / 深度洞察** | 全仓 `年度报告\|yearReview` = **0 命中**；统计只有 4 个总数 + 月字数柱状 + 心情分布横条；**无趋势折线、无写作时段分布、无习惯分析** | Day One / Journey 每年必做年度报告（社交传播引擎） | 中-大，但**纯本地零新能力** |

| 5 | **删单篇日记的显式入口** | `NoteStore.deleteEntry` **存在**，但唯一调用点是「正文清空后保存」（`Editor.ets:733-743`）⇒ 编辑器无「删除本篇」按钮；⚠️ **隐私政策 `Privacy.ets:84` 声称「可在应用内删除单篇日记」—— 政策与实现口径不一致 = 拒审风险** | — | 很小（一个按钮 + 二次确认），**但属合规债，要跟政策对齐** |

| 9 | **搜索增强** | 只搜当前日记本内正文+标签，不区分大小写，**无模糊/拼音/正则/日期区间/组合筛选/搜索历史** | 顶级日记都支持多维筛选 | 小-中 |
| 10 | **编辑历史 / 版本** | 只有 20 层**内存**撤销栈（`Editor.ets:506-534`），**重启即失** | 有版本链/草稿历史 | 小 |

### B. 需要新能力 / 外部流程

| # | 差距 | 卡在哪 |
|---|---|---|
| 11 | **位置标签 / 天气** | 无位置权限（`module.json5` 只有麦克风），无 `geoLocationManager` 调用 |
| 12 | **快捷指令 / 系统日历联动** | 无 `shortcutManager` / `AbilityServiceCtrl` / `CalendarManager` / `WantAgent` |
| 13 | **PDF 导出 / 手写涂鸦 / 音频附件** | 全仓零实现；ASR 刻意**只落文字不存音频**（与 Day One 存音频是刻意区别） |

### C. 主动取舍（不是落后）

- **云同步 / 多设备 / 账号**：隐私政策 `Privacy.ets:24-25` 明写「没有账号、没有登录、没有云端同步」；
  `module.json5` **未申请 INTERNET** ⇒ Day One / Journey / Notion 全都有，我们主动放弃
- **平板分栏**：`Index.ets:137-140` 决策 —— 月历 7 列结构不可变
- **卡片显示统计数字**：结构上做不到（Form 进程无密钥），刻意选「零泄漏」档（`JournalCardData.ets:27-35`）

### D. 我们领先（要当卖点讲）

- **时间胶囊（给未来的信）硬封存** —— 未到期连自己都不能读，不剧透字数/心情/摘要；Day One 无此能力
- **全量本地加密** —— AES-256-GCM + PBKDF2 10 万轮，正文/索引/图片全加密；**Day One 免费版仅传输加密**
- **生物解锁**（HUKS）+ 主密钥只在内存 + 失败即清空
- **多日记本（≤8）+ 自定义模板 + 74 条每日提示**
- **离线 ASR**（只落文字不存音频）
- **零权限零联网 + 系统级备份对账**（`backup_config.json` 含 `vault_pwd.key` ⇒ 换机后原密码可解）

## 四、建议的下一步排期（按「用户感知 × 实现成本 × 零新能力」排序）

**Rock阅读 1.0.10（纯内功，零新能力，零联网）**
1. 屏幕常亮 + 阅读页独立亮度（小，通勤刚需）
2. 导入进度条 + 解析搬 taskpool（改用户天天遇到的最痛点）
3. 书架：标签 / 收藏 / 多选批量 / 列表切换 / 导入去重
4. 统计：累计总字数、WPM 校准、热力图
5. 备份/恢复空壳填实（`EntryBackupAbility`）
6. 自有字体导入（picker，零权限）
7. 书籍详情页 + OPF description 解析

**Rock私记 1.0.8（先补合规与安全基本盘）**
1. **删单篇日记入口**（对齐 `Privacy.ets:84`）＋ 改主密码 ＋ 切后台即锁/闲置超时
2. 富文本补全：标题 / 引用 / 分割线 / 代码块 + 列表真渲染 + 图片入正文流
3. 年度回顾（纯本地，纯逻辑，社交传播引擎）
4. Markdown 导入 + 应用内分享面板 + TXT/MD 导出带图
5. 写作提醒（通知权限 ⇒ **同一提交内改隐私政策两仓 + 产出博客待同步文本**）

**两个应用都要做的**
- 争取一台真机（哪怕二手），把两仓所有「未在真机实测」项跑完 —— 这是投入产出比最高的一件事
- 博客隐私政策麦克风段同步（党哥手动，一次性清掉合规债）

## 五、给党哥的三个决策点

1. **长按查词做不做？** —— 做就要升 `compileSdk` 到 26（会动整个工程的 API 面，回归面大）；
   不做就得接受「阅读器少一个核心交互」。我倾向：**先升 compileSdk 试一次**，只此一项值得。
2. **富文本补全 vs 年度回顾先做哪个？** —— 我倾向**先富文本**：年度回顾是锦上添花，富文本是每天都要用的地基。
3. **是否买一台真机？** —— 我倾向**买**。现在所有新功能的正确性都靠推断，这已经不是「有没有钱」的问题，是「能不能保证不出事」的问题。
