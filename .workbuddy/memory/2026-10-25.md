## 今天的坑（新增）

- **@Builder 值参数不随 @State 重跑**：`this.chip(label, this.someState, cb)` 这种
  直接调用，@State 变了 UI 不一定重绘（ForEach + key 变化的那条路径却是好的）。
  解法二选一：① key 带状态强制重建；② if/else 条件渲染整段重建。
- **UIAbility 没有 `onConfigurationUpdate` 的 super**：ArkTS 能编译，`super.` 运行时抛错，
  表现为**窗口存在但内容全空（黑屏）** —— 排查时差点误判成色板改动炸了。
- **模拟器会自动锁屏**，锁屏后 `aa start` 报 `10106102 device screen is locked`，
  `screenCap` 拍到纯黑（66908 字节，看到这个字节数 = 黑屏）。
  解锁：`keyEvent Power` + `swipe 628 2680 628 700`（从最底边往上滑），
  但**滑动解锁不稳定**，会反复锁上 —— 别把黑屏当代码 bug。
- **dpr = 3.5，视口 ≈ 359vp**（不是 3.0/419vp）：心情条 8vp→28px、柱 72vp→252px 双证实。
- **release 出包命令**：`assembleApp` **不能带 `--mode module`**（报 00306054
  任务不存在）；正确写法 `assembleApp -p product=release -p buildMode=release`，
  产物落在 `build/outputs/release/*.app`（目录名是 product，不是 buildMode）。
  ⚠️ **product 必须是 release**——写成 default 会产出自动签名的调试包，AGC 报 993
  （见下面「993 事故」）。
- `hap-sign-tool verify-app` 的 `-outCertChain/-outProfile` 必须是**存在的本地路径**，
  传 `/tmp/xxx` 会报 11012005。

## ⚠️ 993 事故：两个包同时被 AGC 拒（Profile 文件非法）

提交后 AGC 返回 **993**。抠出包内 Profile 看到 `"type":"debug"` + `debug-info.device-ids`
+ `development-certificate` ⇒ **用的是 DevEco 自动签名（调试证书/Profile）**。
根因：出包命令写了 `-p product=default`，而 default product 的 signingConfig 就是
自动签名；**只改 buildMode=release 不够**（buildMode 只管混淆，不管签名）。
改 `product=release` 重打后，包内 Profile = `type:release` + 正确包名，重新提审。

判别口诀：**993 先抠包内 Profile**（`hap-sign-tool` 的 `-outProfile` 导出后正则找
`"type":"\w+"`），一次就能区分「用错签名 / Profile 失效 / 包名不匹配」，不用去 AGC 猜。

## 鸿蒙生态融入 + 对标世界最佳方案（2026-10-25 晚，党哥点名做生态牌）

- **起步顺序**：服务卡片（零冲突零权限、桌面每天可见）→ 对标批次 A → 智慧搜索 → 小艺建议。
  小艺建议卡 AGC 能力申请（1-3 工作日审核），建议本周先提交占位，不占实现排期。
- **家底比印象好**：bookmarks/highlights 表已带 chapter_index + char_offset 锚点、
  read_sessions 有阅读时长、全文索引已在（1.0.5）——缺的是「把已有数据变成体验」那一层：
  每本书独立排版 / 自动日夜 / 章节剩余时间 / 阅读目标与连续天数 / 笔记跳回原文，
  **五项全都不需要新能力**。
- **真缺口**（对标 Apple Books / Kindle / 静读天下）：per-book 排版（现在是全局
  ReaderPrefs）、自动日夜（4 主题全手动）、本章剩余时间、目标与 streak、
  笔记跳回原文入口、TTS 媒体会话（耳机/锁屏）、自动滚动、自定义主题色。
- **三项生态能力查证结论**：卡片 = FormExtensionAbility + WidgetCard.ets +
  form_config.json（API 10+ 共包方式；FormLink 支持 router/message/call）；
  智慧搜索 = 融合搜索需 `ohos.permission.ACCESS_SEARCH_SERVICE`，本机 DEFAULT_GROUP
  不联网，**建议只索引书名/作者、不索引正文、默认关**；意图框架 = AGC 申请 +
  insight_intent.json + shareIntent + InsightIntentExecutor，云侧 SID 不填即端侧闭环。
- 远期牌：HarmonyOS 7 (API 26) 端侧 AI 检索（Core Vision Kit 文搜图范式）开放后，
  「问这本书」可零云端接入；现在只需保证索引数据结构干净。
