## 七、产品对标与迭代方向（Rock私记 vs 标杆）

**主标杆 Day One**（Apple Design Award / 4.8 分），辅参照 Journey / Diarium / Reflectly。

**已做到（当卖点讲）**：① 加密强度反超免费标杆（AES256-GCM + PBKDF2 10 万次全量本地加密；Day One 免费版仅传输加密）；② **时间胶囊独占护城河**（写给未来的信，到期前连自己都不能读，硬封存不剧透字数/心情/摘要；Day One 无此能力）；③ 统计与洞察扎实（连续天数/最长连续、月字数柱状图、心情分布、月历热力图、那年今日、时间轴、全文+标签搜索、筛选）；④ 数据可携（加密备份 `.rkdbak` + TXT/Markdown 明文导出 + 容错导入）；⑤ 富文本块模型、一天多篇、心情、收藏、标签、桌面卡片、深色模式齐全。

**差距分级**
- **A 类 · 本地就能做，零联网（优先）**：① 语音转文字 ✅ **1.0.6 已实现**（离线 ASR；只落文字不存音频；真机准确率待验）② 位置标签（`@kit.LocationKit`）⬜ ③ 写作提醒（本地推送，把"偶尔写"变"每天写"）⬜ ④ **Markdown 双向 ✅ 2026-11-05 已做**（`data/MarkdownImport.ets`，导出的 `.md` 能读回来，见当日日志；待进 **1.0.11**）⑤ 模板库深化 ✅ 1.0.6 已做自定义模板 ⑥ 多日记本 ✅ 1.0.6 已做 ⑦ PDF 导出 ⬜ ⑧ 每日提示 ✅ 1.0.6 已做
- **B 类 · 需联网，与"非主动联网"冲突（主动取舍，不是落后）**：云同步、云端 AI 回顾、IFTTT 导入。
- **C 类 · 我们领先（卖点）**：全量本地加密、时间胶囊硬封存、完全离线、自研 JSON 十年可读、不绑云账号。
- **坚决不做**：云同步 / 云端 AI —— 守住"数据完全自持"这个与标杆最大的差异化。

## 八、剩余 A 类两项有个共同前提（2026-11-05 核实）

② 位置标签、③ 写作提醒 **都要新权限**（`LOCATION` / `NOTIFICATION` 系），
按第二节纪律：**新权限必须在同一提交内改完隐私政策与 AGC 说明**，不能顺手做。
而且两者都要真机/模拟器才验得出（定位、通知到点弹不弹），不适合"不开模拟器"的场景。

## 九、Rock阅读侧的诊断（2026-11-05 据代码核实，不是凭印象）

**已经齐了**：全文搜索、书签、摘录、目录、主题、翻页、亮度 6 档、常亮、字体族、
简繁转换、TXT 去广告、朗读 TTS（含音色/语速）、自动滚动、统计（连续/成就/本章与全书剩余）、
每日阅读目标（`DAILY_GOAL_STEPS` 0/10/20/30/60，默认 20）、每本书独立排版。

⇒ **阅读器不再是"功能不够"，而是"剩下的活都要用眼睛验"**：
- **EPUB 插图**：`pages/Reader.ets` 里与图片相关的命中几乎为零 ⇒ 书里的图现在读不出来。
  这是对照 Apple Books / Kindle / 静读天下最明显的一处硬差距，
  但要解压取图 + 落沙箱 + 渲染，且**必须看效果**，不开模拟器做不了。
- **阅读进度条**（视觉）
- **翻页动画**（仿真/滑动）

结论：阅读侧下一步该在**能开模拟器的时候**做 EPUB 插图，而不是现在硬写。


## 2026-11-06 十一问定案：路线链（**别再回到「做哪个功能」**）

十一问全部选中推荐项 ⇒ **分歧不在判断，在没人把判断串成一条链**。链如下，改一环要重看后面：

1. **判据**：有陌生人在用并留存（不是"功能追平 Day One"，也不是"审核过就行"）。
2. **人**：鸿蒙上想记录、想安静读书的普通人。优势不是"隐私极客"，是**平台空位**
   —— Day One / Apple Books 都没有鸿蒙版。
3. **分发**：只打磨 AGC 商店页（关键词 / 副标题 / 简介首句 / 前 3 张截图）。
   **不做**社区发帖与内容引流（不持续投入会被淹，更像广告）。天花板 = 个位数日新增。
   ⚠️ 接受这个量级才算诚实：要"几百用户"就必须改策略，别拿商店页骗自己。
   阅读**分开叙事**、打长尾（"TXT 阅读器 / 本地电子书 / EPUB / 离线 / 无广告"），
   不抢"阅读"泛词；"Rock 家族"叙事在商店里没用。
4. **阅读定位**：给**手里已经有书**的人（不能联网供书 ⇒ 没书的人装了也会走）。
5. **私记拆门槛**（核心改造）：不再强制设口令 ⇒ 设备密钥加密落盘，首开直接进首页；
   应用锁变成可选项，且**只是界面拦截**（挡身边人，不防取证，文案要这么写）。
   不做"口令派生密钥"的强加密（双轨 + 双向迁移，风险翻倍）。
6. **存量迁移**：一次性。检出老密文 → 输原密码 → **自动本机备份一份** → 重加密为设备密钥
   → 之后不再出现。`Unlock` 页从"必经"降级为"仅老用户迁移一次"。
   ⚠️ **2026-11-10 实施订正（比原方案更安全，别再按上面那句做）**：实际采用
   **「换包裹层、不重加密全库」** —— 老用户主密钥**不变**，只把「怎么解封主密钥」从
   口令 PBKDF2 换成沙箱随机 `device.key`；迁移 = 原密码解出同一把主密钥 → 自动本机备份 → 写 `device.key`。
   `index.rkd` / `notes/*.rkd` / `img/*.enc` / 老 `.rkdbak` 全部照旧可读，旧 `vault_pwd.key` 保留作回滚点。
   模拟器真实老库端到端实证：9 个文件 md5 迁移前后逐字节一致、二次冷启动免密直达。
   ⚠️ 党哥拍板「密钥排除系统备份」⇒ `backup_config.json` 排除 `device.key`；代价是加密备份
   **只在同一设备、同一应用安装内可恢复**，换机前须导出 TXT / Markdown 明文（文案必须写清）。
7. **数据兜底**：不修 CI（`@kit.CoreSpeechKit` 是专有 kit，修它是为 CI 而 CI）。
   改为给加密/解密/迁移写**零 `@kit.*` 依赖的纯逻辑测试**，用真实老密文喂它，验三条：
   老密文能解 / 迁移后能读 / **中断后原文件还在**。日记丢一次就永久失信。
8. **节奏**：先传已打好的 `1.0.14`/`1.0.13`（闸门全绿，且已修审核级问题）⇒ 审核窗口做拆门槛
   ⇒ 攒 `1.0.15`/`1.0.14` 发。别把打好的包扔掉去等"完美版本"。
   ⚠️ 2026-11-08 订正：这条是 11-06 当时的序号口径；阅读这版 name 已拍板 **`2.0.0`**，
   `1.0.15` 作废（code 仍 `1000016`）。私记 `1.0.14` 与「拆门槛独占窗口」不变。
9. **下版主题**：**写作提醒**（本地通知，留存杠杆最大，不依赖用户反馈）。
   位置标签后置（普通人用率低，展示型）；PDF 导出**不做**（引打印、风险高价值低）。
10. **盲区**：不联网、不收集统计 ⇒ **做不了数据驱动**，只靠 AGC 下载/评分/评论。
    推论：**只做"确定有用"的功能**，需要验证才知道有用的功能一律后置。
