## 一、修复：阅读页「找不到返回书架按钮」

党哥在模拟器打开《呼兰河传》后反馈「没见返回书架的按钮」。

**查证**（设备 `127.0.0.1:5555` 在线，截图 + `dumpLayout`）：

- 常态阅读页 UI 树里**没有**「返回书架」节点 —— `Text('‹')` 只画在 `showMenu=true` 的 `topBar()` 里。
- 点正文文字 `(628,1380)` 前后截图字节完全相同（218413 → 218413）⇒ 正文 `Text` 的
  `copyOption` / `textSelectable(SELECTABLE_FOCUSABLE)` 把点击整个吞掉，父 Column 的
  三区分屏 `onClick` 收不到；点 `HEADER_VP` 空白边距 `(628,200)` 才唤得出菜单。
- 唤出后返回箭头 bounds `[42,171][160,290]`：只有 34vp 的 `‹` 字形，且顶栏 92% `overlay`
  与背后正文叠画 ⇒ 两层叠加，用户既唤不出菜单、也认不出按钮。

⭐ **教训（比代码更重要）**：这条「点文字被吞」11-08 就写进了 `reference-simulator.md`，
但只被记成「uitest 要点空白边距」的**自动化工具坑**，没意识到对真人同样是死路。
⇒ 以后凡「自动化绕过去的点击难点」，一律反问一句「真人这么做会怎样」。

**改动**（`entry/src/main/ets/pages/Reader.ets`；不是新功能，只让既有设计意图真正成立）：

1. 抽 `handleContentTap(xInColumnVp, timestamp)`，Column 与正文 Text 共用一套三区分屏。
2. 正文 Text 补挂 `.onClick`，`event.x + this.marginVp` 还原回 Column 坐标系。
3. `lastContentTapNs` + `ClickEvent.timestamp` 做 1ms 去重，防父子 `onClick` 双触发。
4. `topBar()` 返回控件 `‹` → `‹ 书架`（HIG：返回控件不该只靠符号让人猜），热区保持 ≥44vp。
5. `topBar()` 背景 `palette.overlay` → `palette.bg`（不透明，落实「文字必落不透明面」）。
   ⚠️ **bottomBar 仍透明**，页脚统计与工具栏仍叠画 ⇒ 仍是 P1，本轮没动。

**验证**：单测 **369/369**；debug HAP **BUILD SUCCESSFUL in 20s 12ms**；装机实测
点文字中间 → 菜单出；点「‹ 书架」`(101,230)` → 回书架且「继续阅读」正确更新为
《呼兰河传》50%；右缘点文字 → `2/2`、左缘 → `1/2`（去重没误挡、坐标换算对）；
`longClick 628 1050` → 选区 + 手柄 + 系统菜单（复制/全选/翻译/搜索）完好，**不误弹中央菜单**。
