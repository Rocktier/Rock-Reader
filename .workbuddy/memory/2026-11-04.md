### 2.1 ⭐ 本轮最重要的发现：模拟器没有 PDFKit

```ts
canIUse('SystemCapability.OfficeService.PDFService.Core')   // 模拟器 = false
pdfService  // 运行时是 undefined
```
⇒ 一旦调用 `new pdfService.PdfDocument()` 就是 `Cannot read property PdfDocument of undefined`。
**PDF 的端到端只能在真机验** —— 这不是代码问题，是宿主能力缺失。

应对（三层，全部落地）：
1. `platform/PdfExtract.ets` 先 `canIUse` 探测，只探 syscap **不碰命名空间**
   （`pdfService !== undefined` 会被 ArkTS `arkts-no-ns-as-obj` 在编译期拦掉）；
2. 构造 `new pdfService.PdfDocument()` 整体包 try/catch（探测过了也可能构造失败）；
3. 「用不了」当一等公民：如实文案「这台设备没有 PDF 解析能力，模拟器通常如此，换真机试试」。

### 2.2 ⭐ 验证路径：「验不了机器，就验数据」

桌面真实商业 PDF `价格支持政策明细表2026.3.20.pdf`（80 页）⇒ 电脑上 `pypdf` 抽
`(text, x, y, size)` 成 JSON ⇒ **直接喂给 `readPdf()`**（内核零 `@kit.*`，node 里能跑）。

这条路径是**三个真 bug 的唯一发现途径**，纯造数据绝对造不出来：
1. **一份表转出 109 个 `###`** —— 9pt 占 24.8% 的正文被当成标题；
2. **产出假表格** `|  |  | 1. 电 | 容感 | 应 脚感冲水2.一 |` —— 判据太松；
3. **间距被抹平** —— 分栏/表格列全糊成一串。

### 2.3 三条被真实数据逼出来的判据（写进内核 + 单测）

| 判据 | 规则 | 逼出来的原因 |
|---|---|---|
| **标题两档** | `≥ 正文×1.5` 直接算标题；`1.15~1.5` 倍必须**罕见**（占比 ≤ 8%）才算 | 真实样本字号 `7.5pt 74.8% / 9pt 24.8% / 12pt 0.5%`；先试「少数派 ≤25%」仍不够（16pt 标题被拒）|
| **页眉四条件** | 页上下 8% 带内 + 字号 ≤ 正文×1.1 + 跨页重复 + 出现页数 ≥ 半数 | 封面 22pt 大标题压在页面顶部，被当页眉剔掉（4 条单测同红）|
| **表格四门槛** | 列数 ≥3、连续 ≥3 行、≥80% 行每列都占到、归类失败 ≤5% | 否则就出假表格；不合就当段落 |

另：**间距即版面语义** —— `gap > size * 0.9` 就补空格，与语言无关（中文之间也补，因为是分栏不是连字）。

### 2.7 ArkTS 三坑（本轮复现，已进 MEMORY 第十一节）

① `null` 与 `undefined` 是两种类型；② 非空断言 `!` 不允许；

## 5. AGC 自检报「语音转文字不生效」—— 查出 4 个版本的真 bug

党哥贴来自检报告（性质：**可提升项，不影响上架**；他自己发现 1.0.8 审核通过时后台就有这条，只是当时没看）：

> 测试步骤：主页-编辑文章-语音：语音转文字不生效
> 测试环境：WIFI联网、HarmonyOS 7.0.0(HUAWEI Pura 80 Ultra)、API26.0.0(26)、中文环境

**根因（确凿，非误报）**：`AsrService` 里 startListening 的 extraParams 键名写成 `recognizeMode`，
官方是 **`recognitionMode`**（re-cogni-**tion**-Mode）。键名是字符串 ⇒ 编译器查不出 ⇒
引擎按"没传"处理 ⇒ 落到默认值 **1 = 外部 writeAudio 喂音频流**，而我们从没喂过
⇒ **引擎起了、权限有了、界面显示"正在聆听"、但永远没声音没结果，全程零错误码**。
1.0.6 / 1.0.7 / 1.0.8 / 1.0.9 四个版本一直带着。

**为什么之前没发现**：前三版只验到"引擎能起"（云真机绿点 + 「语音转文字中…」），
从没验过"真能识别出字" —— 云真机没有麦克风通道，模拟器没离线引擎。
今天云调试那次"ASR 三步全通"的结论**要打折扣**：只证明了创建引擎与权限两步。

**官方证据**（四处一致，都用 recognitionMode）：
- 官方指南 device.harmonyos.com/cn/docs/apiref/harmonyos-guides/speechrecognizer-guide
- 华为开发者联盟博客 topic/03217184346412144（并明确写"不传默认 1"）
- 华为开发者联盟论坛 topic/0204213980272610089
- 官方 API 示例的 createEngine 还带 `extraParams: {locate:'CN', recognizerMode:'short'}` —— 我们原来**完全没给**

**修复**（commit `0429104`）：
- 键名改正 + 抽出 `AsrText.asrEngineExtra()` / `asrStartExtra()` 两个纯函数，让单测盯字符串键名
- createEngine 补 locate + recognizerMode
- `vadEnd` 由默认 800ms 放宽到 3000ms（默认值会在换气处把长句切断）
- 单测 **253/253**（+6 条键名守门）；debug 与 release 编译均通过

**顺带记下的判据**：云测机器人不会说话 ⇒ 语音类功能在自检里被判"不生效"有结构性成分，
但**不能当噪音忽略**（这次就是真 bug）。分辨靠 HiLog：
有 `asr: onResult` 回调 = 音频进来了识别不出；**一个回调都没有 = 音频压根没进来**。
