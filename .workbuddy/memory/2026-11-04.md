### 1.3 关键决定（第一性原则）
- **存档只存 .md，不存结构 JSON** ⇒ 单一真源，永远不会「文件里是 A、界面显示 B」。
  代价是每次打开重新解析（几毫秒），换来的是 Reading 与 文件必然一致。
- **写解析器而不是序列化 AST**：因为「阅读应用」意味着用户会丢一个 .md 进来，
  没有解析器这条路根本不存在。258/258 单测，含真实 docx 产物 round-trip 逐字相同。
- **行号换算走写出器**（`writeBlockPieces` + `blockStartLines`），不在界面层重拼。
  错位的行号比没有行号更糟 —— 会让用户去改一行本来没错的字。
- **转换中不做假进度**：设计稿画了逐块吐字，当前一次算完 ⇒ 只给文字进度，不画百分比。

### 2.1 ⭐ 本轮最重要的发现：模拟器没有 PDFKit

```ts
canIUse('SystemCapability.OfficeService.PDFService.Core')   // 模拟器 = false
pdfService  // 运行时是 undefined
```
⇒ 一旦调用 `new pdfService.PdfDocument()` 就是 `Cannot read property PdfDocument of undefined`。
**PDF 的端到端只能在真机验** —— 这不是代码问题，是宿主能力缺失。

应对（三层，全部落地）：
1. `platform/PdfExtract.ets` 先 `canIUse` 探测，只探 syscap **不碰命名空间**
   （`pdfService !== undefined` 会被 ArkTS `arkts-no-ns-as-obj` 在编译期拦掉）；
2. 构造 `new pdfService.PdfDocument()` 整体包 try/catch（探测过了也可能构造失败）；
3. 「用不了」当一等公民：如实文案「这台设备没有 PDF 解析能力，模拟器通常如此，换真机试试」。

### 2.2 ⭐ 验证路径：「验不了机器，就验数据」

桌面真实商业 PDF `价格支持政策明细表2026.3.20.pdf`（80 页）⇒ 电脑上 `pypdf` 抽
`(text, x, y, size)` 成 JSON ⇒ **直接喂给 `readPdf()`**（内核零 `@kit.*`，node 里能跑）。

这条路径是**三个真 bug 的唯一发现途径**，纯造数据绝对造不出来：
1. **一份表转出 109 个 `###`** —— 9pt 占 24.8% 的正文被当成标题；
2. **产出假表格** `|  |  | 1. 电 | 容感 | 应 脚感冲水2.一 |` —— 判据太松；
3. **间距被抹平** —— 分栏/表格列全糊成一串。

### 2.3 三条被真实数据逼出来的判据（写进内核 + 单测）

| 判据 | 规则 | 逼出来的原因 |
|---|---|---|
| **标题两档** | `≥ 正文×1.5` 直接算标题；`1.15~1.5` 倍必须**罕见**（占比 ≤ 8%）才算 | 真实样本字号 `7.5pt 74.8% / 9pt 24.8% / 12pt 0.5%`；先试「少数派 ≤25%」仍不够（16pt 标题被拒）|
| **页眉四条件** | 页上下 8% 带内 + 字号 ≤ 正文×1.1 + 跨页重复 + 出现页数 ≥ 半数 | 封面 22pt 大标题压在页面顶部，被当页眉剔掉（4 条单测同红）|
| **表格四门槛** | 列数 ≥3、连续 ≥3 行、≥80% 行每列都占到、归类失败 ≤5% | 否则就出假表格；不合就当段落 |

另：**间距即版面语义** —— `gap > size * 0.9` 就补空格，与语言无关（中文之间也补，因为是分栏不是连字）。

### 2.4 PDF 读入器结构

| 层 | 文件 | 职责 |
|---|---|---|
| 内核 | `core/read/pdf/PdfLayout.ets`（~1050 行）| 行聚类 / 字号判标题 / 行距切段 / 页眉剔除 / 表格识别，**零 `@kit.*`** |
| 内核 | `core/read/pdf/PdfTextReader.ets` | `readPdf(pages, sourceName)`；三通道 `LAYOUT/PLAIN/NONE`；`structureInferred` **恒 true** |
| 平台 | `platform/PdfExtract.ets` | PDFKit 调真实文件 → `PdfPageText[]` |
| 分派 | `ConvertService.convertPdf()` / `ConvertRunner` | 真进度「正在读第 N / M 页」|

- `structureInferred` 一路传到 `Archive` 索引 → `Reader` 元信息行 → `Report` 的 `InferredNote()`
  ⇒ 用户能分清「这个 `##` 是真的还是猜的」。
- 扫描件（`getGraphicsObjects` 无文本）⇒ 不当空文档，如实说「可能是扫描件，要 OCR」。
- `MAX_PAGES = 500`，截断时把「这份 PDF 有 N 页，只转了前 500 页」拼进 message。

### 2.7 ArkTS 三坑（本轮复现，已进 MEMORY 第十一节）

① `null` 与 `undefined` 是两种类型；② 非空断言 `!` 不允许；
③ `arr[k].field !== undefined ? arr[k].field : ''` **收窄失效**（两次下标是不同表达式）⇒ 先 `const x = arr[k]`。
另有：**布尔变量不做类型收窄**（`overridden ? linesOverride : collected.lines` 报 undefined 不可赋值）⇒ 内联判空。
