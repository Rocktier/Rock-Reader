## 深夜：Rock阅读 两个功能落地（自动滚动 + TTS 媒体会话）

> 党哥指令：「自动滚动（Rock阅读）— 静读天下招牌能力，通勤场景直接命中；
> TTS 媒体会话（Rock阅读）— 代码注释已经给你留好位置了，切后台就停是明确体验缺口。做这两个先」

### 1. 新增文件（4 个源码 + 2 个测试）

| 文件 | 作用 |
|---|---|
| `entry/src/main/ets/data/AutoScroll.ets` | 自动滚动**纯逻辑**（不引 `@kit`）：速度档、剩余时间、到底判定、菜单三态、浮层闸门 |
| `entry/src/main/ets/engine/tts/AvSessionState.ets` | 媒体会话**纯逻辑**：三态视图 ↔ 媒体命令的映射、倍速归一化 |
| `entry/src/main/ets/engine/tts/AvSession.ets` | AVSession SDK 封装（`@kit.AVSessionKit`），所有调用包 try/catch，失败只记日志 |
| `test/autoscroll.test.ts` / `test/avsession.test.ts` | 13 + 12 条单测 |

**设计口径**：速度以「**每页停留秒数**」计（8/6/4/3/2，默认 4）。本应用是**分页**渲染（每页正好一屏），
「按行滚动」没有对应物；「几秒翻一页」用户能直接换算成「一章大概读多久」，通勤够用。

### 2. AVSession 三条硬约束（写进文件头）

1. **失败必须降级** —— SDK 任何一步失败只记日志，绝不连累朗读（媒体会话是锦上添花，朗读是主线）。
2. **不需要 `-keep`** —— 注册的是闭包回调，不是按名反射的类实现（与 ASR 的 `RecognitionListener` 情况不同）。
3. **不要用 `BackgroundPlayMode`** —— 那是 API 24+，本工程 API 20 用不了。

`module.json5` 加 `"backgroundModes": ["audioPlayback"]`（**合法值是 `audioPlayback` 不是 `audio`**，写错报 00303038）。
⚠️ 这是「后台模式」声明不是权限 ⇒ `requestPermissions` 仍为空，零权限叙事不受影响。
⚠️ AGC 后台「版本管理 → 权限管理 → 后台模式 → 音频」要勾选并填用途，否则驳回。

### 3. ⭐ 自动滚动 × 朗读必须互斥（实测踩到）

同时开会互相打断：滚屏每翻一页就 `tts.seekTo(range.start)` 一次，音频被反复重载，
日志表现是 `onStart` 每 2 秒一个新 id + `onComplete stale, dropped` ⇒ 听感「跳着读」。
⇒ `startSpeak()` 先 `stopScroll()`；`startScroll()` 若在朗读则 `stopSpeak()` + toast「已停止朗读，开始滚屏」。
（要「边听边翻」用手动翻页即可：朗读本来就跟手动翻页走。）

### 4. ⭐ 浮层与滚屏的联动：两次重构才收敛

**第一版（错）**：在「开浮层时暂停、关浮层时恢复」—— 要在 **6 处** `showMenu/showToc/showSettings`
的赋值点同步两套状态，漏一处就是「菜单关不掉还接着在背后滚」的幽灵 bug。
**第二版（对）**：**到点才判断** —— `onScrollTick()` 里
`if (!scrollTickAllowed(showMenu, showToc, showSettings, showHighlight)) return;`
浮层开着这一拍就不翻页，浮层一关下一拍自然继续。**状态只有一处，没有影子状态。**

配套三条：
- **浮条在菜单期间不画**（`&& !this.showMenu`）—— 菜单的 bottomBar 就在同一位置，两条叠着会互相盖，
  实测菜单一开浮条的「关闭」就点不到（落点被 bottomBar 吃了）。
- **菜单里的「滚屏」按钮是三态自描述**：OFF→`滚屏` / RUNNING→`停滚屏` / PAUSED→`继续滚屏`。
  ⚠️ 一个按钮覆盖三态时，**按了会发生什么必须写在按钮上**；都写「滚屏」的话，
  用户在「已暂停」时按下会以为是「继续」、实际却是「关掉」。
- **PAUSED 必须映射到 RESUME 不能映射到 STOP**（单测守死这一格）。

### 5. 回后台：挂起 ≠ 暂停

`onPageHide` 停表但**不改状态**（仍是「正在滚」），`onPageShow` 自动续上 ——
通勤场景里用户锁屏看两眼就回来，回来接着滚才是对的；改成 PAUSED 会让用户以为自己按过暂停。
⇒ 独立的 `scrollSuspended` 标志，与「用户主动暂停」区分开。

### 6. ⚠️ ArkUI V1 陷阱再确认（家族记忆第 2 条的又一次验证）

`this.scrollState === ScrollState.OFF ? '滚屏' : ...` 这种**就地读 @State** 才能被依赖插桩追到。
写成 `this.scrollMenuLabel()`（读取藏进方法体）⇒ 文案被定格在首次求值的值。
⇒ 菜单按钮最终用**就地三元展开**，纯逻辑层只出 `scrollToggleOf(state)`（返回枚举，不返回文案）。
