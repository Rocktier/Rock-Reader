## 六、第 1 项：结论反转（重要，别再当 bug 修）

`EntryBackupAbility` 只打两行日志 —— 我一度判定是"空壳 bug"，**错了**。查证结果：**官方明说空实现就是推荐做法**。

顺带查出的真问题是 `backup_config.json` 里只有 `{"allowToBackupRestore": true}`，没写 `includes`。但多方资料指向"数据库、缓存目录等默认可被备份"，**官方样例本身就是无 includes 的空实现并明说这是有效默认**。
⇒ 按党哥第一性原则：**现在不能下结论**。贸然写 `includes` 若路径写错反而**缩小**备份范围，那才是真灾难。
⇒ 定性只能走真机（克隆 或 设置→系统和更新→备份与恢复）。**模拟器验不了。**
⇒ 若设备操作不便，就先不改配置、上架文案一个字不提（家族纪律：没实测不许写"已修复"）。

备份体积取舍（待党哥定）：`database/` + `preferences/` 只有几十 KB 且**不可重建**（丢了书架就重建不出来，书变沙箱孤儿）；`files/`（小说正文）等于全部藏书体积但用户能重导。我倾向先只锁前两个。

## 七、卡点：模拟器灌不进书（明天第一件事）

三条路都排除，别重复踩：

1. `aa start -a EntryAbility -b com.rocktier.rockreader -U file:///data/local/tmp/probe.txt`
   → AMS `[permission_verification.cpp121] verify fail`，**want.uri 被剥离**。而 `takeIncomingUri` 判空就静默 return、连日志都不打，容易误判成"导入没跑"。
2. `aa start -A ohos.want.action.viewData -t text/plain -U file://...`
   → 系统弹「**暂无可用打开方式**」。注意 module.json5 里 2026-09-23 的对照实验矩阵写着：**纯 type（无 uri）能命中列表第一位，带 file:// uri 的一律不命中** —— 所以这次可能是我多带了 `-U`，明天可以试 `-A ... -t text/plain` 不带 uri 看是否真能进列表。
3. `hdc file send` 到 `/storage/media/100/local/files/Download` 等公共目录
   → 目录不存在 / Permission denied / no such file；**只有 `/data/local/tmp` 可写**；`mkdir` 也被 SELinux 拒。

**家族 memory 里已验证可用的兜底（优先试这个）**：
> `hdc file send` 可直接写应用沙箱的偏好/DB 文件 —— 先 `aa force-stop`，删掉 `-wal/-shm/-dwr/-compare` 残件再推。

即：force-stop → 往 `filesDir` 推 probe.txt → 改 then sqlite DB 插 books/chapters 行 → 冷启动，书架就该出现这本书。这条路能同时喂给第 3 项做口径对比。

已记录在 Task #126。
