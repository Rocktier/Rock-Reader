# 设计基准：Apple HIG + 鸿蒙 HDS（2026-11-06 立，全家族硬要求）

**唯一基准 = <https://developer.apple.com/cn/design/>《人机界面指南》**（鸿蒙侧对照
<https://developer.huawei.com/consumer/cn/design/>）。**UI 类 skill 只起优化作用，不能起决定作用**；
与 HIG 冲突一律以 HIG 为准。适用 Rock 家族 + all2md + 以后所有应用。

## 一、硬指标（做界面时逐条量，不靠感觉）

| 项 | 要求 |
|---|---|
| 点击目标 | **推荐 44×44pt；绝对最小 28×28pt** |
| 对比度 | ≤17pt 全字重 **4.5:1**；≥18pt 或粗体 **3:1**；深色浅色**各自**要过 |
| 字号 | iOS 默认 17pt、**最小 11pt**；避免细体字重；字样种类要少 |
| 文字放大 | 至少支持放大 **200%**，放大后不许截断/重叠（横排该改竖排） |
| 颜色 | **不许只用颜色传达信息**（配形状/图标/文字）；禁止硬编码系统语义色 |
| 布局 | 重要内容靠上；缩进表达层级；相关项分组；遵守安全区 |
| 动效 | 尊重「减少动态效果」，降级为瞬时 |

⚠️ 家底好的地方别推翻：all2md 的 `Tokens.ets` 已是量化 token，只补缺口。

## 二、平台分层（苹果与华为各管一层）

**HIG 管可量化硬指标，HDS 管平台视觉语言**（毛玻璃、渐变模糊、按压弹性、悬浮圆角），两者不冲突。

- HDS「沉浸光感」**生效范围有限**：普通组件只在 Navigation 标题栏 / 底部 TabBar 生效
  ⇒ 内容区大卡用通用 `backgroundBlurStyle`，**不假装接了 HDS**（官方也说「光感不能牺牲操作效率」「耗 GPU」）。
- Apple《材质》：**Liquid Glass 不在内容层用**；玻璃优先给浮层 / 抽屉（背后有正文才透得出来）。
- 半透明只写组件 `.opacity()`；**资源色一律 6 位**（8 位被静默吞成透明）。
- ⭐ **淡化 ≠ 降对比度**：说明 / slogan 用 11fp + `muted` + 留白退后，4.5:1 照守，**文案一字不改**。
- ⭐ **动效别用 `if (entered)` 包内容** ⇒ @State 数值 + `.animation()`。

## 三、重点色块与字号双峰（2026-11-06 两仓改版立）

- **要立焦点就立"一块墨"**：首屏只留**一个**实心色面，其余退到纸面 —— 靠面积与反差立重点，
  不靠加粗描边。改版前的共同病是"每个元素都在说话"，于是没有重点。
- 语义色**成对** `heroBg`/`heroText`，四套主题各给一套，页面零 `if (isDark)`。
  ⚠️ **深色下不能拿 `text` 反白**（86% 白 ⇒ 一块白卡压纯黑），取抬一档的卡片灰。
- **字号双峰**：一页只留两档（30–38 与 11），中间层全撤。小字**不得低于 11fp**。
- **动效** `common/Motion.ets`（两仓各一份，纯数值 + 纯函数可单测）：`motionMs(base, reduced)`
  降级返回 **0**（瞬时，不是变慢）、`staggerMs(index, cap)` **必须封顶**。
  ⚠️ **入场只用位移/缩放，不用 opacity** —— `entered` 万一没翻成 true，"动效没播"会变成"内容不见了"。

## 四、「减少动态效果」怎么接（2026-11-06 三仓已接）

- 读 `settings.display.ANIMATOR_DURATION_SCALE`（`@ohos.settings`，d.ts 原话 **0 = 动画立即结束**）。
  ⚠️ 标 `@deprecated since 21` —— compileSdk 20 暂安全，**升 21 要回来换实现**。
- 分工硬规矩：**纯判断放 `Motion.ets`、SDK 读取放 `SystemMotion.ets`** ——
  引 `@ohos.settings` 或 `$r()` 的文件进不了 node:test（all2md 把纯函数塞 `Tokens.ets`，测试直接 `$r is not defined`）。
- ⚠️ **`Number('')` 是 0 不是 NaN** ⇒ 必须显式挡空串，否则"读不到"被判成"用户要关动画"，
  动效静默全没且看着像设计决定。降级时连 `setTimeout` 都别排（闪一帧 = 内容闪一帧）。
- 唯一观测手段：`hilog.info(DOMAIN, 'Motion', 'anim scale=%{public}s', v)`。模拟器读不到设置入口 ⇒ 真机验。

## 五、审计三抓手（打磨前先跑，别凭感觉）

1. **字号分布** —— **必须查 token 值**（`RR_FS_MICRO`=9、`RJ_FS_META`=10 那批），只扫字面数字会漏一大半。
2. **点击目标** —— `.height(<44)` + 同块 `onClick`，再分「有 `responseRegion`（视觉小=合规）」与「没有」。
3. **对比度全组合** —— **别漏「强调色当底」**（主按钮正是 `fontColor(bg)` on `backgroundColor(accent)`）；
   判读时剔掉永不出现的理论组合。半透明色先 flatten 到实际底色再算。

## 六、四条实操结论（本轮踩出来的）

- ⭐ **不达标优先改 token，不改调用点**（阅读 67 处、私记 62 处）。
  代价：11fp 会甩孤字（设置页把 `a）` 甩到单独一行）⇒ 处理方式是**显式断行、断在语义边界**，不是缩文案。
- ⭐ **主按钮字色不是 `bg`**：那是"拿页面底色当字色"，语义跟着主题漂移 ——
  四个主题三个碰巧过线，护眼新苔压蓝底只有 4.34:1 ⇒ 与 hero 同款再立一对 `onAccent`。
- ⭐ **热区 44 要让位于「不压邻居」**：私记图片删除角标视觉 24、热区 40（缩略图间距 8、中心距 72，
  44 会串到隔壁）。绝对下限 28 必须守，推荐值 44 可以让。
- 图标按钮视觉小不怕，**加 `responseRegion` 即可**；`Checkbox` 20×20 用
  `.responseRegion({ x: 0, y: -12, width: 44, height: 44 })`。

## 七、HDS 侧补充口径（2026-11-08 重读官方页，与 HIG **取严者**）

- ⭐ **深色模式正文 >5:1**（华为比 HIG 的 4.5:1 更严）；浅色 >4.5:1；
  大字号 / 辅助文本 / 功能图标 >3:1；**文字对比度上限 17.6:1**（防刺眼）。
  ⇒ 全家族判据：**浅色 4.5:1、深色 5:1**，两仓 `theme.test.ts` 断言照此写。
- ⭐ 官方深色模式明写「**应用内避免黑白跳转的页面**」、层级 / 色彩语义 / 同类控件风格
  三者与浅色一致 ⇒ **系统浅色而应用纯黑**同样算不一致。主题默认应跟随系统，
  应用内纸色只能是用户**显式选择**的内容层偏好（不能按钟点偷偷切）。
- 沉浸光感（HarmonyOS 7 首页口径「空间美学」「围绕空间感…和谐美学」）：六特性、
  强 / 均衡(默认) / 弱三档、开发推荐 `ADAPTIVE`；官方明写「**光感不能牺牲操作效率**」
  「耗 GPU」「除弹窗 / Slider / Toggle 外，普通组件只在 Navigation/NavDestination 标题栏、
  底部 TabBar 生效」「亮色非纯白底建议 GENTLE」「API23 及更早 Web 同层渲染会异常透明」。
  ⇒ 内容区用通用 `backgroundBlurStyle` 是对的，**不要假装接了 HDS**。
- 手机字号 **≥12vp 推荐 / 最小 8vp 必须**；与家族「最小 11fp」并存时取严：
  **12 作推荐值，11 作绝对下限**。
- 设计原则：Concise / Smooth / Intuitive / Emotional / Universal；中文「简洁高级」=
  平衡性 + 层级性（深度靠明度 / 模糊，平面靠字号 / 饱和度 / 大小）、降低信息密度、
  适当留白、突出最重要任务、界面一致易学易用。

## 八、三层空间模型与渐变边界（2026-11-08 视觉重设计定稿）

- ⭐ **光 / 材质 / 文字三层**：① 光 = `linearGradient({ angle:165, colors:[[haloTop,0],[bg,0.62]] })`
  **只铺空白底层、不放任何文字**；② 材质 = 不透明 `card` + 1px `glassEdge` + 12vp 圆角，
  玻璃**只给抬手唤出的浮层**；③ 文字 = 全落在 `card` / `overlay`(92% 不透明) 上，可算可测。
  ⇒ **阅读 / PDF 正文区反 HDS**：均匀纸面、禁渐变禁玻璃，四套纸色保留为内容层偏好。
  两仓共用的是这套**结构语言**，不是主色。
- ⭐ **卡与底色差只有 1.06–1.19:1** ⇒ 层次必须靠 1px 描边 + 圆角 + 轻投影，不许只靠颜色。
- ⭐ **跟随系统照抄 Journal 已验证方案**：`common/Appearance.ets`（纯逻辑三态 +
  `resolveDark` / `paletteNeedsRefresh`）+ app 层 `COLOR_MODE_NOT_SET` +
  `onConfigurationUpdate(newConfig)` **只读回调参数**换 AppStorage 色板 + `onForeground` 兜底。
  ⚠️ **运行时 `setColorMode` 会重建 UIContent、丢页面栈**（Journal 10-16 实测退回桌面）；
  ⚠️ 首帧色板要在 `loadContent` 之前定，且 `@State` 初值（`Index.ets:151` /
  `Reader.ets:305` / `Settings.ets:32`）也要一起改，否则先黑一帧。
  官方接入：`arkts-environment`（`Environment.envProp` + `@StorageProp`）、
  `arkts-light-dark-color-adaptation`、`bpta-dark-mode-adaptation`（均已查证）。
- **对比度实测（WCAG flatten）**：浅 `text #E6000000` on `#FFFFFF` = **17.58:1**
  （HDS 上限 17.6 ⇒ **正文色不许再加深**）；深 `accent #317AF7` on `card #1D232D` =
  **3.95:1** ⇒ 卡上蓝字改用 `accentOnCard #6BA0FF`(6.09:1)，accent 原值留给进度条/图标；
  深 `text3` 50% 白 = 5.02:1 贴线 ⇒ 提到 56% `#8FFFFFFF`(5.90:1)；
  浅 `text3` 在渐变最亮端 `#DCE8FA` = 4.68:1 ⇒ **文字一律不上渐变层**。
- **两仓主色独立**：阅读蓝 `haloTop #DCE8FA/#16233A → bg #F1F3F5/#101318`，
  `card #FFFFFF/#1D232D`；私记暖 `haloTop #F7EBDC/#241D16 → bg #FAF8F3/#12100E`，
  `card #FFFFFF/#26211C`，`glassEdge #E8E0D4/#4A3F33`。
- **版本窗口**：阅读 **2.0.0 / 1000016** 只做 P0（跟随系统 + 设置入口拆分 + 书架空间化，零数据风险）；
  私记 1.0.14 **独占拆门槛**，视觉排其后。**审核期不动包**。
- **不做**：正文渐变 / 书架卡铺玻璃 / 胶囊 TabBar / 统一三仓主色 / 运行时 setColorMode /
  8 位 hex 进 `color.json` / 为淡化降对比度 / 数据迁移。
- 交付：桌面 `Rock家族-视觉重设计-2026-11-08/`（清单 + 视觉稿 HTML，已用系统 Edge
  无头渲染 1400×6800 校验）。

## 九、上机复评补充（2026-11-08 深夜，清单 §7.1）

- ⭐ **「文字必落不透明面」不是 92%**：排版抽屉用 `#EB000000` / `#EBFFFFFF` 的
  `palette.overlay`，浅 / 深两套都看得见背后正文与控件文字叠画；中央菜单浮层干脆透明，
  页脚统计文字与 bottomBar 重叠（**点击后 1s 的稳定态截图 ⇒ 不是转场动画**）。
  ⇒ 浮层要守这条硬指标，背景得是**100% 不透明**（或给文字单独垫不透明块），
  8% 透出就足以让对比度失去确定值。这是既有问题，列 P1。
- **启动窗口是系统层、不是应用层**：`startWindowBackground` 只能跟系统深浅色
  （资源限定符 base/dark），此阶段读不到应用内偏好 ⇒ 别把「显式选深色 + 系统浅色
  仍闪一下」当 bug 追，也**绝不能用运行时 `setColorMode` 修**（会丢页面栈）。
- **9:16 裁切口径**：1256×2760 → `top=0` 裁 1256×2233 → resize 1080×1920；
  底部 `LOCAL ONLY` 装饰性标语会被裁掉（可接受），但**功能性入口不许落在被裁区**。
- **跟随系统 ≠ 全局一个开关**：书架 / 设置页读全局偏好，阅读页读每本书覆盖；
  老用户存过显式 `theme=dark` 时升级后仍全黑 ⇒ 「新默认值」不等于「用户体感变了」，
  发版前必须问一句**存量数据怎么办**。

## 十、字族纪律（2026-11-09 党哥「字体怪怪的」定案）

- ⭐ **一个页面只用一种字族**：不写 `fontFamily` 即系统默认黑体（HarmonyOS Sans），
  层级只靠字号 / 字重 / 留白 / 颜色。**不许用换字族来做层级**。
- **病根样本**（私记首页改前）：13 处 `monospace` 日期 + 3 处 `serif` 日记摘要 +
  2 处 `letterSpacing(2)` 中文标题 ⇒ 一屏 3 种字族，每行在「等宽 → 衬线」间跳一次。
  党哥原话「阅读应用的字体很舒服」——阅读正文 `serif` 用量 **0**，全屏一个字族。
- ⚠️ **`serif` / `monospace` 是通用族别名**，落到哪款系统字体由 OS 决定，跨设备不可预期；
  「不指定」才既能跟随系统字体设置、又稳定。**别改成写死字体名**。
- ⚠️ **中文标题别加 `letterSpacing`**：中文不需要字距，2vp 会让中英混排散开、
  Latin 与 CJK 间距不均。
- 数字对齐靠 `textAlign(Center)` + `width('100%')`，**不靠等宽字族**（私记月历 42 格已验）。
- ⭐ **2026-11-10 党哥追加（下版待办，2.0.0 不动）**：「有些数字好像不是黑体的，
  记得也统一掉」⇒ 2.0.0 只清了首页，**下一版把私记剩余 46 处全清**（39 `monospace`
  + 7 `letterSpacing`），范围是**全应用**、不限于统计页。精确清单见十·一。
  ⚠️ 上一条「辅助页可留」的边界**已被此条覆盖**，不要再拿它当挡箭牌。
- ⚠️ **别误伤 Rock阅读**：阅读应用也有 76 处 `monospace`（Reader 39 / Stats 13 /
  Index 10 / Settings 6 / PdfReader 4 / About 3 / Privacy 1），但**正文视线内不混排**，
  所以看着舒服。党哥说「跟阅读一样的黑体」指的是**观感**，不是要连阅读仓一起改；
  真要两仓全统一，须另问一句才动手。
