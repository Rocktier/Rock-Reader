## 五、AGC「应用内点击操作完成快」不通过 → 两仓性能整改（21:40 接单）

**报告原文**：检测值 **2666.0ms**，AGC 目标线 2400ms，官方标准 ≤900ms。
测试环境：WIFI 联网 / HarmonyOS 6.1 (Mate 60) / API 6.1.1 (24) / 中文环境。定性「暂不影响上架」。

### 检测项口径（已查证官方文档，别再猜）
- 全名「应用或元服务内**点击操作完成快**」，与「点击操作**响应**快」（≤100ms）是**两项不同的检测**。
- 测的是**墙钟**：手指抬起（ACTION_UP / H:DispatchTouchEvent type=1）→ **页面转场 lane 结束**
  （H:ABILITY_OR_PAGE_SWITCH 等）。官方文档：`performance-delay`（架构文档时延章）。
- ⇒ **转场画不出来 = lane 结束被推后**。所以「点击后主线程被同步重活堵住」= 直接超标。
- 官方给的优化方向：多任务并发、UI 组件自身创建耗时 → 合理优化代码逻辑。

### 两仓根因（并行子代理排查 + 我复核）
**Rock私记（头号嫌疑，秒级常数）**
- `security/KeyCustody.ets` 的 `deriveKek()` 用 `kdf.generateSecretSync(spec)`，
  PBKDF2 **10 万轮**跑在**调用线程**上；调用链是「解锁按钮 onClick → recoverByPassword → deriveKek」
  ⇒ 整段 KDF 在 UI 主线程一口气跑完，中间零帧产出。
- SDK 官方注释明写：同步版「may take a long time and block the main thread …
  advised to invoke synchronous API within a child thread to avoid blocking it」。
- SDK 核实：`Kdf.generateSecret(spec): Promise<DataBlob>`（d.ts:6212）存在，
  与同步版**共用同一套 PBKDF2Spec / 同一算法**（官方 PBKDF2 指南把三种调用形式并列列出）⇒ **派生结果一致**。
- ⚠️ 注意：`data/VaultService.ets` 里的 `generateSecretSync` **只出现在注释里**，实际代码没有 KDF
  （子代理初判有误，已复核）。真正的 KDF 调用点只有 KeyCustody 三处。

**Rock阅读（开书路径，O(整章)）**
- `Reader.ets`：`loading=false` 与 `openChapter()`（整章 `layoutSync` 排版 + 整章读链）
  **挤在同一个 JS task** ⇒ ArkUI 没机会出帧 ⇒ `LoadingProgress` 画不出来、用户看到白屏卡住。
- `surveyChars()` 原来 **`i % 8 === 7` 才让一帧** ⇒ 一次连读 8 章（EPUB = 8 次解压+解析）焊死主线程。
- `surveyChars()` **原先完全没有取消机制**：离开阅读页仍在跑，下一次开书还在抢 UI 线程。
- 另：`applyPrefsToLayout()` 用 `prefs.getLevels()`（全局）算签名，而抽屉显示的是
  `effectiveLevels(bookId)`（每书覆盖）⇒ **口径不一致 ⇒「没改任何东西」也判定成「变了」→ 白白整章重排**。

### 已做的改动（低风险，不动安全参数）
**私记**
1. `deriveKek` / `recoverLegacy` 改异步 `await kdf.generateSecret(spec)`；
   `recoverLegacy` 由同步函数改 async（调用点本来就 `await`，兼容）。
   **迭代次数 100000 一个没动** —— 这次动的是「在哪个线程跑」，不是「算多少次」。
2. 新增 `security/KdfParams.ets`（**纯逻辑，不引 SDK ⇒ 可单测**）：算法名/算法串/迭代次数/密钥长度
   **唯一真源**，`test/kdfparams.test.ts` 6 条守门测试锁死（参数漂移 = 老用户打不开日记）。
3. `Unlock.ets` 加 `busy` 态：点击后**同一同步块内**换文案（「正在解锁…」/「正在建立保险库…」）+ 禁用按钮
   ⇒ 点击后立刻有界面变化，转场 lane 提前结束。校验失败**不置 busy**（先报错，别先转菊花）。
4. 顺手修 `common/AppMeta.ets` 版本漂移（1.0.5/1000006 → 1.0.6/1000007）：
   1.0.6 发版时改了 `app.json5` 漏改 AppMeta ⇒ smoke 测试一直红着。**发版纪律：版本号两处一起改。**

**阅读**
1. 新增 `deferHeavyWork(work)`（`setTimeout(0)`，**必须宏任务**：微任务不会让出到渲染管线）。
   用在：`init()` 开书、`onAreaChange` 首帧兜底、`applyPrefsToLayout` 重排。
2. `surveyChars()`：**每章让一帧**（原每 8 章）+ 每章查取消标志、见位即退 + 每轮开始清标志。
3. 新增 `data/Survey.ets`（纯逻辑）+ `test/survey.test.ts` 6 条守门测试（粒度=1、取消语义）。
4. `applyPrefsToLayout` 改用 `effectiveLevels(bookId)`（消除「没改也重排」）。
5. 目录/书签/摘录/搜索结果四处跳章统一走 `gotoChapterAndClose()`：**先关抽屉、下帧再跳章**
   （顺序不能反：先跳章会让「关抽屉」也被同步块堵住）。
