### 4.1 Rock阅读 —— 划词「加入摘录」（全链路打通）

**先纠正昨天记错的一条**：「`onTextSelectionChange` / `editMenuOptions` 都是 API 26 起、本工程 20 用不了」——**错的**。
查 SDK 26 `component/text_common.d.ts` 实测：`onTextSelectionChange` **@since 11**、`textSelectable` **@since 12**、
`editMenuOptions` **@since 12**；只有 `SelectionContainer` **组件本身** @since 26 ⇒ **不用升 compileSdk**。

**四个真坑（按踩到顺序）**：

1. **`.gesture(LongPressGesture())` 挂在正文 Text 上 ⇒ 系统长按选词完全不出现**
   （截图无手柄无菜单、UI 树 0 个 TextMenu 节点）—— 自定义手势**抢赢**了 Text 自带的长按选词。
   ⇒ **长按必须完整让给系统**，摘录面板改由「加入摘录」菜单项唤起。
2. **选区只选中 1 个字**（中文长按默认粒度）⇒ 之前「少于 2 字就丢弃」的门槛把用户点击变成**死路**
   （点了「加入摘录」毫无反应）。⇒ 门槛降级成「要不要提示用户选区偏短」，**进面板只看空不空**。
3. **`onMenuItemClick` 返回 `true`（完全拦截系统默认逻辑）⇒ 系统浮动菜单留在屏幕上**，
   浮在我们自己的面板上面。⇒ **返回 `false`**（我们的逻辑先跑，系统默认逻辑照跑 ⇒ 收起菜单）。
4. **残留选区手柄撤不掉**：compileSdk 20 的 `UIContext` **没有** `clearFocus`（API 26 才有），
   切 `textSelectable` 也**撤不掉已建立的选区**。⇒ 正解：
   `Text(content, { controller })` + `TextController.setTextSelection(0, 0)` + `closeSelectionMenu()`。
   ⚠️ 残留手柄会**压在抽屉页签上**（正文左上角），点页签反而重新弹系统菜单 ⇒ 页签点不动。

**最终交互**：长按正文 → 系统选区（可拖手柄扩选）→ 菜单「加入摘录」（在 ⌄ 溢出菜单里）
→ 我们的摘录面板**预填精确选中的那句**（可选色 + 写注 + 可编辑）→ 存下 → 标记页签可见。
整页快照的老路径降级为中央菜单里的「摘录」按钮。
